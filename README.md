# Optical Calculator

머신비전 광학 계산기. PC 브라우저와 휴대폰에서 같은 코드로 동작하는 PWA입니다.

## 실행

**`run.bat` 을 더블클릭하면 됩니다.** 서버가 뜨고 브라우저가 열립니다.
검은 창을 닫으면 서버도 꺼집니다.

**파일을 고치면 브라우저가 알아서 새로고침합니다.** 저장만 하면 화면이 바뀌므로,
확인하려고 APK 를 다시 만들거나 폰에 옮길 필요가 없습니다. PC 에서 다 보고
다 됐을 때만 배포하면 됩니다.

- 앱: http://127.0.0.1:8123/index.html
- 공식 검증: http://127.0.0.1:8123/verify.html

포트를 바꾸려면 인자로 넘깁니다 — `run.bat 8124` 또는:

```bash
python scripts/dev_server.py 8124
```

### 개발 서버가 기본 http.server 대신 필요한 이유

`python -m http.server` 로도 열리기는 하지만 두 가지에 걸립니다.

**브라우저가 ES 모듈을 캐시합니다.** 파일을 고치고 새로고침해도 예전 코드가 그대로
돌아갑니다. 개발 서버는 `Cache-Control: no-store` 를 붙여 이걸 막습니다.

**localhost 는 보안 컨텍스트라 서비스 워커가 등록됩니다.** 오프라인 캐시가 먼저
응답해버려서, 강제 새로고침을 해도 옛날 화면이 나옵니다. 개발 서버는 페이지를 열 때
등록된 서비스 워커와 캐시를 지웁니다.

`index.html` 을 탐색기에서 그냥 더블클릭하면 **빈 화면만 나옵니다.** ES 모듈이라
`file://` 로는 브라우저가 스크립트를 막습니다. 반드시 서버를 거쳐야 합니다.

### 고쳤는데 옛날 화면이 나온다면

원인은 대개 둘 중 하나입니다.

**예전 서버가 포트를 잡고 있습니다.** 창을 제대로 닫지 않으면 파이썬 프로세스가 남습니다.
새 서버가 뜬 것처럼 보여도 요청은 옛 서버로 갑니다. 개발 서버가 이걸 감지하면 실행을
거부하고 안내를 띄우지만, 이미 떠 있는 것부터 정리해야 합니다.

```bash
powershell -Command "Get-Process python | Stop-Process -Force"
```

**서비스 워커가 남아 있습니다.** localhost 는 보안 컨텍스트라 서비스 워커가 등록되고,
그 캐시가 페이지보다 먼저 응답합니다. 개발 서버는 `/sw.js` 요청에 자기를 지우는 워커를
내려주므로, 한 번 새로고침하면 정리됩니다.

입력값이 이상하다면 계산기 화면의 **기본값으로 되돌리기** 를 누르세요. 입력값은
계산기별로 브라우저에 저장되므로, 값을 바꿔 보다가 원래대로 못 돌아갈 때 씁니다.

### 휴대폰에서 볼 때

PC와 같은 Wi-Fi에 접속한 뒤 PC의 LAN 주소로 들어갑니다. `run.bat` 이 창에 후보 주소를
출력합니다. `192.168.*` 또는 `10.*` 로 시작하는 것이 보통 맞고, `172.*` 는 WSL·Hyper-V
가상 어댑터라 대개 연결되지 않습니다. 윈도우 방화벽이 물으면 허용해야 합니다.

폰에서도 자동 새로고침이 동작하므로, 손에 들고 보면서 고치는 것도 됩니다.

`verify.html`은 UI 없이 계산 코어만 확인합니다. 공식을 고친 뒤에는 이 페이지가 전부 PASS인지
먼저 보고 넘어가세요.

## 구조

```
core/
  units.js      단위 변환, 표시용 반올림, 표준 초점거리 목록
  profile.js    장비 프로필 · 즐겨찾기 (localStorage)
  registry.js   계산기 등록소, 대분류 정의, 검색
  render.js     화면 렌더러 (전 계산기 공용) + 해시 라우팅
calc/
  lens.js       렌즈 대분류 계산기 정의 + 공식
pwa/
  icon.svg
manifest.json   설치 정보
sw.js           오프라인 캐시
verify.html     공식 검증
```

핵심은 **계산기가 화면이 아니라 정의 객체라는 점**입니다. `calc/*.js`에 객체 하나를 추가하면
홈·대분류·검색·즐겨찾기·상세 화면이 전부 자동으로 따라옵니다. 화면 코드는 건드리지 않습니다.

## 계산기 추가하는 법

`calc/` 에 정의 객체를 넣고 `core/registry.js`의 `RAW` 배열에 합칩니다.

```js
{
  id: 'my-calc',
  category: 'camera',              // CATEGORIES 의 id
  name: '표시 이름',
  summary: '한 줄 설명',
  tags: ['검색어', '검색어'],
  related: ['다른-계산기-id'],
  formula: [                       // 계산 단계마다 한 줄씩. 문자열 하나만 줘도 됩니다
    '중간값 = 입력A × 입력B',
    '결과 = 중간값 / 입력C',
  ],
  en: 'English Name',              // 국문 옆에 흐리게 붙는 통용 영문 용어
  inputs: [
    { key: 'a', label: '라벨', en: 'Label', unit: 'mm', default: 10, min: 0, step: 0.1,
      profile: 'workingDistance' },   // profile 키를 주면 장비 프로필이 기본값을 채운다
  ],
  outputs: [
    { key: 'b', label: '라벨', en: 'Label', unit: 'mm', digits: 2, primary: true },
  ],
  compute(v) { return { b: v.a * 2 }; },       // 순수 함수. DOM 을 참조하지 않는다
  warn(v, o) { return [{ level: 'warn', text: '…' }]; },  // level: info | warn | danger
}
```

입력 방향이 여러 개인 계산기는 `inputs`/`outputs`/`compute` 대신 `modes` 배열을 쓰면
상단에 탭이 생깁니다. `calc/lens.js`의 `lens-select`가 예시입니다.

`compute` 가 반환하는 키 중 `_` 로 시작하는 것은 화면에 표시되지 않습니다.
`warn` 에 넘길 중간값을 담는 용도로 씁니다.

### 도해 규약

`diagram(v, o)` 는 SVG 요소 배열을 반환합니다. 반환값이 없으면 도해 없이 숫자만 나옵니다.

```js
diagram(v, o) {
  return [fovRect(o.fovW, o.fovH, { targetW: v.fovW, targetH: v.fovH, axis: o._axis })];
}
```

`core/diagram.js` 가 제공하는 것:

| 함수 | 보여주는 것 |
| --- | --- |
| `fovRect(w, h, opts)` | 시야 사각형 + 가로·세로 치수. `targetW/H` 를 주면 검사 대상을 점선으로 겹쳐 여백을 보여줍니다 |
| `opticalLayout({...})` | 센서·렌즈·대상 측면도. WD 와 f 가 어느 구간인지 표시 |
| `depthRange({...})` | 초점면 기준 앞뒤 심도 구간 |
| `pixelGrid({...})` | 픽셀 한 칸의 실제 크기와 검출 한계 |
| `focusDepthView({...})` | 수렴·발산 원뿔과 센서를 옮길 수 있는 범위 |
| `thinLensView({...})` | 대상·렌즈·상 배치와 물체거리·상거리 |
| `imageCircleView({...})` | 이미지 서클 안에 센서 사각형이 들어가는지 |
| `motionBlurView({...})` | 노출 중 번진 자국이 픽셀 몇 개에 걸치는지 |
| `rollingShutterView({...})` | 리드아웃 때문에 기울어진 형상 |
| `refractionView({...})` | 경계면에서의 입사·반사·굴절 광선 |
| `plateShiftView({...})` | 유리를 지나며 밀린 초점과 어긋난 경로 |
| `angleOfViewView({...})` | 렌즈에서 퍼지는 화각 원뿔과 시야 |

**라벨은 반드시 "용어 + 수치 + 단위" 로 씁니다.** 도형만 있고 값이 없으면 용어 설명 그림일
뿐이고, 값만 있고 도형이 없으면 위의 결과 카드와 다를 게 없습니다. 둘이 붙어 있어야
"이 용어가 그림의 이 구간이고, 지금 값은 이것" 이 한눈에 읽힙니다.

축척은 맞추지 않습니다. WD 300 mm 와 센서 23 mm 를 같은 축척으로 그리면 납작해져
읽히지 않습니다. 대신 개략도임을 그림 안에 명시합니다. 다만 `opticalLayout` 의 f 는
WD 에 대한 비율을 반영하므로, 초점거리가 작동거리에 비해 얼마나 짧은지는 눈으로 보입니다.

색은 CSS 변수로만 지정합니다(`style.css` 의 `.d-*` 규칙). SVG `marker` 는
`context-stroke` 대신 `currentColor` 를 쓰는데, 구형 안드로이드 WebView 가
`context-stroke` 를 그리지 못하기 때문입니다.

### 수식 표기 규약

`formula` 는 **계산 단계마다 한 줄씩** 배열로 적습니다. 한 줄에 쉼표로 이어 붙이면
어디까지가 한 식인지 읽히지 않습니다.

```js
// 이렇게
formula: [
  '배율 = 초점거리 / (WD − 초점거리)',
  'FOV (W) = 센서 크기 (W) / 배율',
]

// 이렇게 말고
formula: 'm = f / (WD − f),   FOV = S / m'
```

**현장에서 부르는 이름을 그대로 씁니다.** 판단 기준은 "실무에서 뭐라고 말하는가" 입니다.

| | 쓰는 표기 | 예 |
| --- | --- | --- |
| 영어로 말하는 것 | **영문 그대로** | FOV, WD, DOF, CoC, NA, BFD, DR, ROI, fps, SNR |
| 한국어로 말하는 것 | **국문 그대로** | 초점거리, 배율, 상거리, 센서 크기, 화소수, 노출 시간, 굴절률 |
| 한 글자 기호 | **쓰지 않음** | `f`, `b`, `S`, `N`, `m`, `c` |

`시야`, `작동거리` 처럼 국문으로 직역하면 오히려 낯섭니다. 현장에서 FOV, WD 라고
말하므로 그대로 씁니다. 반대로 `초점거리` 를 `f` 로 줄이면 무슨 값인지 알 수 없습니다.

`sin`, `atan`, `log₂` 같은 함수 이름과 `n₁` 같은 첨자는 그대로 둡니다.

**라벨도 같은 표기를 씁니다.** 수식이 `FOV (W)` 인데 라벨이 `시야 (W)` 이면
눈으로 이어지지 않습니다.

**축이 있는 값은 `(W)` / `(H)` 를 붙입니다.** 라벨과 수식이 같은 표기를 써야
`배율 (W) = 센서 크기 (W) / FOV (W)` 를 읽고 화면에서 그 값을 바로 찾을 수 있습니다.

| 값 | 라벨 | 수식 표기 |
| --- | --- | --- |
| 센서 물리 크기 | `센서 크기 (W)` · `Sensor (W)` | `센서 크기 (W)` |
| 시야 | `FOV (W)` · `Field of View (W)` | `FOV (W)` |
| 화소수 | `화소수 (W)` · `Width` | `화소수 (W)` |
| 대상 분해능 | `대상 분해능 (W)` · `Spatial Resolution (W)` | `대상 분해능 (W)` |
| 작동거리 | `WD` · `Working Distance` | `WD` |

중간값이 있으면 그 줄을 먼저 적고 다음 줄에서 씁니다. 두 축에서 각각 구한 뒤 하나를
고르는 계산은 그 선택 과정도 한 줄로 드러냅니다.

```js
formula: [
  '배율 (W) = 센서 크기 (W) / FOV (W)',
  '배율 (H) = 센서 크기 (H) / FOV (H)',
  '배율 = 둘 중 작은 쪽 — 그 축이 제약축입니다',
  '초점거리 = WD × 배율 / (1 + 배율)',
]
```

**수식에 쓴 값은 입력이나 출력으로 화면에 있어야 합니다.** 그 줄에서 바로 정의하는
중간값은 예외입니다. 화면에 없는 값을 수식에서 쓰면 따라 읽을 수 없습니다.

### 영문 용어 규약

`en` 은 필수는 아니지만 **계산기·모드·모든 입출력 항목에 붙이는 것을 원칙**으로 합니다.
렌즈와 카메라 스펙시트가 전부 영문이라, 국문 라벨만 있으면 스펙시트와 대조가 안 됩니다.

- 업계 통용 표기를 그대로 씁니다. `FOV`, `WD`, `DOF`, `CoC`, `Airy Disk`, `F-number`
- 직역하지 않습니다. 시야 → `Field of View` 가 아니라 실제로 쓰는 `FOV`
- 검색은 `en` 값까지 훑으므로 `Nyquist`, `CoC` 같은 영문으로도 계산기가 찾힙니다

## 안드로이드 APK

같은 소스를 Capacitor 로 감싸 APK 를 만듭니다. 웹 파일이 APK 안에 통째로 들어가므로
설치 후에는 인터넷도, GitHub Pages 도 필요 없습니다.

```bash
npm run apk
```

`dist/OpticalCalculator-<버전>-debug.apk` 가 나옵니다. 폰에 복사해 설치하면 됩니다
(설정에서 "출처를 알 수 없는 앱" 허용 필요).

### 처음 한 번만

```bash
npm install
```

```bash
npm run android:init
```

`android:init` 이 안드로이드 프로젝트를 만들고, 이 환경에 필요한 설정을 심고, 런처
아이콘까지 생성합니다. `android/` 는 git 에 올리지 않는 재생성 가능한 산출물이라,
지우고 이 명령을 다시 돌리면 그대로 복구됩니다.

### 필요한 도구

| 도구 | 비고 |
| --- | --- |
| Node.js LTS | `winget install OpenJS.NodeJS.LTS` |
| Android Studio | `winget install Google.AndroidStudio` — 설치 후 **첫 실행 마법사를 Standard 로 완료**해야 SDK 가 받아집니다 |
| JDK 21 | `winget install Microsoft.OpenJDK.21` |

**JDK 는 21~23 이어야 합니다.** 위아래로 막혀 있습니다.

- Capacitor 7 이 Java 21 이상을 요구합니다. JDK 17 이면 `invalid source release: 21`
- Gradle 8.11 이 Java 24 이상의 클래스 파일을 읽지 못합니다. Android Studio 번들
  JBR(25)을 쓰면 `Unsupported class file major version 69`

빌드 스크립트가 설치된 JDK 를 훑어 이 범위에 드는 것을 골라 씁니다. 없으면 설치 명령을
안내하고 멈춥니다.

환경변수(`JAVA_HOME`, `ANDROID_HOME`)는 설정하지 않아도 됩니다. 스크립트가 표준 설치
위치에서 직접 찾습니다. 비표준 위치에 깔았다면 `CAPACITOR_JAVA_HOME` 으로 지정하세요.

### 이 환경 특유의 문제 두 가지

저장소가 `기타 소스` 아래에 있어 **경로에 한글이 들어갑니다.** AGP 는 이걸 감지하면
빌드를 거부하므로 `android.overridePathCheck=true` 를 넣어 우회합니다. 같은 이유로
`local.properties` 에 SDK 경로를 쓰지 않습니다 — properties 파일 인코딩에서 한글이
깨집니다. 대신 환경변수로 넘깁니다. 두 가지 모두 `scripts/patch-android.mjs` 가
`cap sync` 마다 다시 심습니다.

Gradle 호출은 `package.json` 에서 `cd android && gradlew.bat` 로 엮지 않고
`scripts/build-apk.mjs` 를 거칩니다. cmd 와 sh 에서 실행 경로 해석이 달라지고,
Node 20 부터는 `.bat` 을 셸 없이 spawn 하면 거부되기 때문입니다.

### 배포용 서명

`npm run apk` 가 만드는 것은 **디버그 서명 APK** 입니다. 사내 배포나 테스트에는
그대로 써도 되지만, Play 스토어에 올리거나 정식 배포하려면 릴리스 키로 서명해야
합니다. 그때 `npm run apk:release` 와 키스토어 설정을 붙이면 됩니다.

- 휴대폰: 배포 주소 접속 → 브라우저 메뉴 → "홈 화면에 추가"
- PC: Chrome/Edge 주소창 우측 설치 아이콘 → "앱으로 설치"

`sw.js` 덕분에 한 번 열어두면 오프라인에서도 동작합니다. 파일을 고쳐 재배포할 때는
`sw.js` 상단의 `CACHE` 버전 문자열을 올려야 사용자에게 새 버전이 내려갑니다.

서비스 워커는 `https` 또는 `localhost` 에서만 등록됩니다. 사내망 http 주소로 배포하면
계산은 정상 동작하지만 오프라인 캐시는 걸리지 않습니다.

### 엔코더 · 트리거 (`calc/encoder.js`)

이송을 따라 라인을 찍을 때 트리거 보드에 넣을 값을 구합니다.
이 값이 맞지 않으면 Y 방향 배율이 틀어져 상이 늘어나거나 눌립니다.

| 계산기 | 내용 |
| --- | --- |
| 엔코더 분해능 · 스케일러 | 실측 / 두 지점 측정 / 로터리 엔코더 / 필요 사양 역산 4가지 방식 |
| 분주비 · 트리거 펄스폭 | 분주비, 최대주파수, 펄스폭 설정값, 트리거 출력 주기 |

분주비는 트리거 보드에 정수만 들어가므로, 반내림·반올림 각각의 Y 분해능을 함께 내고
이미지 분해능과 몇 % 차이 나는지 경고합니다. 5 % 를 넘으면 상이 눈에 띄게 늘어납니다.

로터리 엔코더 분해능은 원주율을 `Math.PI` 로 계산합니다. 기존 엑셀 시트가 `3.14` 를
쓴다면 값이 0.05 % 정도 차이 납니다(48 mm 롤러에서 7.5398 과 7.536).

## 용어 설명

`core/glossary.js` 에 용어 115개가 정의돼 있습니다. 홈의 **용어 설명** 카드나 `#/terms`
로 들어가면 목록과 검색이 있고, 홈 검색창은 계산기와 용어를 함께 찾습니다.

### 계산 중에 바로 뜻 보기

계산기 화면의 **수식·입력 라벨·결과 라벨**에서 아는 용어에 점선 밑줄이 그어집니다.
누르면 짧은 뜻이 팝업으로 뜨고, 거기서 용어 설명 페이지나 관련 계산기로 갈 수 있습니다.
화면을 떠나지 않으므로 입력하던 값이 그대로 남습니다.

꾹 누르기(long-press)를 쓰지 않은 이유는 세 가지입니다. 모바일에서 텍스트 선택과
충돌하고, 누를 수 있다는 표시가 없어 기능을 발견하기 어렵고, PC 에는 대응 동작이
없습니다. 점선 밑줄은 그 자체가 표시가 되고 탭 한 번으로 열립니다.

### 용어 추가하는 법

```js
{
  id: 'my-term',
  term: 'DOF',              // 화면 라벨·수식에 쓰인 표기와 정확히 같아야 합니다
  en: 'Depth of Field',
  category: 'lens',
  aliases: ['피사계심도'],   // 같은 뜻으로 쓰이는 다른 표기
  short: '한 문장 정의.',    // 팝업에 뜨는 줄
  body: '두세 문장 설명.',   // 상세 페이지 본문
  calc: 'dof',              // 관련 계산기 id
  related: ['coc', 'f-number'],
}
```

`term` 이 라벨과 다르면 밑줄이 생기지 않습니다. 라벨 표기를 바꿀 때는 여기도 같이
고쳐야 합니다.

**빠진 용어는 `verify.html` 이 알려줍니다.** 계산기의 입출력 라벨 411개 중 몇 개가
용어와 연결되는지를 재고, 80 % 아래로 떨어지면 실패로 잡습니다. 화면 어디에도 표기가
없는 용어(밑줄이 생길 자리가 없는 용어)도 함께 보고합니다.

100 % 를 목표로 하지는 않습니다. `기준 거리`, `측정 길이`, `출력 가로` 처럼 일상어로
읽히는 라벨까지 등재하면 밑줄이 너무 많아져 정작 어려운 용어가 묻힙니다.

용어 찾기는 긴 표기를 먼저 맞춰 `대상 분해능` 이 `분해능` 으로 잘리지 않게 합니다.
경계 판정은 국문과 영문이 다릅니다. 영문 약어는 앞뒤 모두 글자가 아니어야 하고
(`DRAM` 의 `DR` 을 잡지 않도록), 국문은 앞만 봅니다. `F수를`, `배율이` 처럼 조사가
바로 붙기 때문에 뒤까지 막으면 본문에서 거의 걸리지 않습니다.

## 안드로이드 뒤로가기

하드웨어 뒤로가기를 누르면 화면 계층을 따라 올라갑니다.

```
계산기 → 대분류 → 홈 → "앱을 종료하겠습니까?"
용어 상세 → 용어 목록 → 홈
```

용어 팝업이나 종료 확인 대화상자가 열려 있으면 그것부터 닫습니다.

`core/backnav.js` 가 `@capacitor/app` 의 `backButton` 이벤트를 받아 처리합니다.
기본 동작은 웹뷰 히스토리를 따라가다 바로 앱이 꺼지는데, 계산기 화면에서 종료되면
곤란하므로 계층 이동으로 바꿨습니다. 종료 확인 대화상자가 열려 있으면 먼저 닫습니다.

웹 브라우저에서는 아무것도 하지 않습니다. 브라우저 뒤로가기가 이미 자연스럽게 동작합니다.

## 계산 규약

- 박막렌즈 근축 근사 기준입니다. 주점 간격을 반영하지 않으므로 실제 렌즈에서는 오차가 있습니다.
- 센서 크기는 포맷 프리셋(1/2", 2/3" 등)이 아니라 `픽셀수 × 픽셀 크기`로 계산합니다.
- 가로·세로 요구 배율이 다를 때는 **작은 쪽**을 택합니다. 큰 쪽을 쓰면 반대 축이 시야를 벗어납니다.
- 피사계심도의 허용 착란원 기본값은 센서 픽셀 크기 × 2입니다. 현장 기준이 다르면 입력에서 배수를 바꾸세요.
- 센서측 초점심도와 물체측 피사계심도는 `초점심도 = 피사계심도 × 배율²` 로 이어져 있습니다.
  `calc/shared.js` 의 `depthOfField` 가 두 값을 한 식에서 함께 내므로 한쪽만 고쳐 어긋날 일이 없습니다.
- **센서 픽셀 크기**(Pixel Pitch)와 **대상 분해능**(Spatial Resolution)은 다른 값입니다.
  앞은 센서 위 픽셀의 물리 크기, 뒤는 그 픽셀이 대상에서 차지하는 크기이며
  `대상 분해능 = 센서 픽셀 크기 ÷ 배율` 입니다.
- 회절 파장은 가시광 550 nm 고정입니다.
